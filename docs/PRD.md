# PRD: Nosy — 개발 환경 진단 펫

## 목표
여러 개발 도구의 개별 진단(doctor) 결과를 하나로 모으고, 문제가 있으면 정확히 어느 파일 몇 번째 줄을 어떤 명령으로 고치는지 안내하며, 화면 위에 투명한 창으로 직접 상주하는 데스크톱 펫.

## 문제 정의와 차별점 (결과보고서 원재료)
이 절은 결과보고서의 **개발배경 및 목적**, **혁신성 및 차별성**, **기대효과** 항목에 그대로 쓰기 위한 원재료다.

### 푸는 문제 (우선순위 순)
1. **진단이 원인을 짚어주지 않는다.** `flutter doctor` 같은 도구는 "무엇이 문제인지"는 말해도 **어느 파일 몇 번째 줄을 고쳐야 하는지**는 알려주지 않는다. → 증상 → **원인 파일:줄 번호** → 고치는 명령어로 번역한다.
2. **진단 도구가 흩어져 있고 존재조차 모른다.** `brew doctor`·`flutter doctor`·`npm doctor`가 각자 따로 있고 많은 개발자가 있는 줄도 모른다. → 설치된 도구를 자동 감지해 관련 doctor를 모두 돌리고 **하나의 헬스 스코어로 통합**한다.
3. **환경은 서서히 망가진다.** PATH 충돌, 죽은 alias, 고아 환경변수가 쌓이며 조용히 무너진다. **"works on my machine"의 실체가 이것**이다. → 마지막 정상 스냅샷과 비교해 **드리프트를 즉시 감지**한다(`docs/specs/drift-detection-spec.md`).
4. **(2차 서사) 코딩 에이전트가 막히는 이유의 상당수는 코드 버그가 아니라 환경 문제다.** 작업 전에 "이 프로젝트를 돌릴 준비가 됐는지" 미리 확인할 수 있다. → v1에서는 MCP 노출을 제외했으므로(위 "MVP 제외 사항") **보고서의 "향후 확장성 및 기대효과"에서 다룬다.**

### 차별점 — 선언적 적용 도구가 아니라 진단 도구다
**이 구분이 차별성 항목의 핵심이므로 보고서와 영상에서 명확히 한다.**

| 부류 | 대표 | 하는 일 | 우리와의 관계 |
|---|---|---|---|
| **선언적 적용** | `chezmoi`, `dotbot`, `donnemartin/dev-setup` | 미리 정의한 설정을 **적용**한다 | **다른 범주다.** 이들은 "이렇게 만들어라"를 실행할 뿐, **지금 상태가 정상인지 판단하지 않는다** |
| **개별 진단** | `brew doctor`, `flutter doctor`, `shellrc-doctor` | 자기 영역만 진단한다 | **결합 대상.** 어댑터로 흡수·통합한다 |
| **통합 진단(우리)** | — | 여러 도구의 진단을 모으고 원인을 지목하며 **시간에 따른 변화를 추적**한다 | 검색상 **선례 없음** (단, 제출 전 한 번 더 재확인 권장) |

**핵심 주장: 새 기술을 발명하지 않는다.** 이미 흩어져 있는 개별 진단 능력을 어댑터로 결합하는 것 자체가 가치다. 이 서사가 OSS 적절성(2-5) 항목의 근거가 된다(`docs/SUBMISSION.md` "심사 기준 참조").

## 사용자
로컬 개발 환경(셸 rc 파일, 버전 매니저, Homebrew, git, Docker)을 macOS에서 관리하는 개발자. 1차 타깃은 2026 오픈소스 개발자대회 심사위원 — 10월 기능테스트에서 자기 머신에 직접 설치해 실행한다.

## 핵심 기능
1. 어댑터 5종(shell-rc, version-manager, homebrew, git, docker)이 각자 진단을 수행하고 단일 헬스 스코어로 통합한다. 이 중 shell-rc·version-manager(1·2번)가 "증상→파일:줄→고치는 명령" 차별점을 지고, homebrew·git·docker(3·4·5번)가 "흩어진 doctor를 하나의 헬스 스코어로" 통합 서사를 진다.
2. 설정 파일에서 비롯된 문제는 파일:줄 번호와 원문 발췌(evidence)를, 그 외 문제는 실행 가능한 수정 명령(fix.command)을 반드시 동반한다 — "증상 → 원인 파일:줄 → 고치는 명령"이 핵심 차별점.
3. 마지막 정상 스냅샷과 비교해 드리프트(새로 생긴 error)를 감지하고, 펫이 즉시 alarmed 상태로 전환된다.
4. 온스크린 펫(투명·항상 위·프레임 없음)이 헬스 스코어에 따라 idle/thinking/worried/alarmed 상태를 표시한다.
5. 클릭 → 말풍선 → 토글 패널에서 파일 경로·줄·발췌·수정 명령을 확인하고, 토글로 실제 수정을 실행한다(실행 전 확인 + 백업 + sudo 자동실행 금지 + 되돌리기 가능 여부 표시).

## MVP 제외 사항
- MCP 서버 노출 — 보고서·영상에서 향후 계획으로만 언급
- 3D 캐릭터 — 렌더러 격리로 교체 가능하게만 설계 (`docs/ADR.md` ADR-001)
- Linux/Windows 어댑터 — 코드 분기는 열어두되 지원은 macOS만 명시 (`docs/specs/pet-window-spec.md`)
- Docker 컨테이너 기반 통합 테스트 — 시간이 남으면 리눅스에서도 도는 어댑터에 한해 추가 검토(완전 배제는 아님, `docs/SUBMISSION.md` "증거 자료로서의 CI")
- `shellrc-doctor` 원본 저장소에 PR 기여 — 이슈 1건만 남긴다 (`docs/SUBMISSION.md` "커뮤니티 접점")
- `packages/core`의 CLI 제품화 — 영구 제외, 내부 개발/테스트 전용 (`docs/ADR.md` ADR-005)
- 파괴적 fix — 파일·패키지 삭제, 전역 설정 초기화 (`docs/specs/toggle-panel-spec.md`)

## 디자인
- 온스크린 펫: 투명 배경 · 항상 위(always-on-top) · 프레임 없음 · 작업 표시줄 미노출 · 드래그로 이동 가능
- 클릭 관통(`setIgnoreMouseEvents`)은 펫 영역 밖에만 적용해 작업을 방해하지 않는다
- 2D 스프라이트로 확정(3D는 1차 합격 후 또는 대회 이후). 렌더러는 `<PetView state={...} />` 단일 컴포넌트로 격리해 교체 비용을 낮춘다
- 상세 패널은 토글/스위치 형태의 자체 UI다 — 실제 OS 설정 화면을 조작하지 않는다
- 세부 색상·타이포그래피 등 비주얼 디자인 시스템은 아직 정의되어 있지 않다 → `docs/UI_GUIDE.md` 참조 (미정으로 표시됨)
