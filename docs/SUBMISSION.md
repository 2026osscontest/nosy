**함의 2 — 10월 기능테스트는 심사위원이 직접 설치해서 돌린다.** 서명 없는 `.dmg`는 macOS Gatekeeper에 막혀 그 자체로 기능테스트 실패가 된다. → **`pnpm install && pnpm dev`가 주 경로이며 README 최상단에 온다. `.dmg`는 시간이 남을 때만 만드는 보조 산출물이며, 제공하더라도 Gatekeeper 우회 방법을 함께 문서화한다.** 일정이 밀리면 `.dmg`를 가장 먼저 버린다(`docs/TIMELINE.md` "포기 우선순위" 참조). **서명되지 않은 `.dmg` 하나에 기능테스트의 성패를 걸지 않는다.**

**함의 3 — 라이선스 검증이 독립 심사 항목이다.** 소스코드는 8/27에 고정 제출되므로 라이선스 문서는 8/27 안에 완결해야 한다 (아래 라이선스 체크리스트).

**별도 파일 제출 불가.** 유튜브 업로드 후 URL만 보고서에 기재한다. 업로드·처리 시간을 일정에 포함하고, 계정은 미리 준비한다. 미공개(일부공개) 설정 여부는 제출 직전 확인한다. (구성안은 `docs/TIMELINE.md` 참조)

### 프로젝트명
수상 시 상장에 그대로 새겨진다. **특수문자 제외, 핵심 키워드 중심.** 참가 접수 정보와 동일해야 하므로 접수 시 기재한 이름을 먼저 확인한 뒤 확정한다.
**현재 미확정** — 늦어도 D8(8/26)까지 확정할 것.

### 붙임1 — SBOM
요구 항목: 번호 / 라이브러리명 / 버전 / **라이선스** / 공식 저장소 URL / **사용 목적 및 주요 기능**

- **작성 규칙: 의존성을 추가하는 그 순간 SBOM 행도 함께 추가한다.** 마지막에 몰아서 쓰면 Electron 트리 전체를 역추적해야 한다.
- 직접 의존성만 기재하되, 판단이 애매하면 포함하는 쪽을 택한다.
- 의존성 하나가 표의 한 줄이므로, 새 의존성 추가는 사전 승인 원칙(`docs/TIMELINE.md` "작업 진행 원칙")이 여기서 실제 비용으로 돌아온다.

### 붙임2 — AI 활용 명세서
우리는 제출 대상이다. 유형 1·2·3(프로젝트에 AI 모델을 탑재한 경우)은 모두 해당 없음이다 — 코딩·디버깅 보조용 상용 AI 단순 활용은 체크 대상이 아니라고 양식이 명시한다.

그러나 **4번 항목("상용 AI 보조도구 활용 여부 및 범위")은 모든 유형 필수 작성**이다.

- 유형 체크: 1·2·3 모두 미체크 (탑재 모델 없음)
- 2·3번 항목: "해당 없음"
- 4번 항목 기재 방향: **범위를 축소해 적지 않는다.** 실제 분담(`docs/TIMELINE.md` "작업 진행 원칙")을 그대로 쓴다 — 요구사항 정의·아키텍처 설계·스펙 확정·코드 리뷰 및 채택 판단은 참가자가 수행하고, 구현 코드 작성은 Claude Code를 활용했다는 사실을 명시한다.
- 대회 규정상 AI 보조도구 활용은 금지가 아니다. 양식이 "체크하지 않고 4번에 기재하라"고 별도 항목을 둔 것 자체가 허용의 근거다. 축소 기재했다가 나중에 드러나는 것이 훨씬 큰 위험이다.

## 커뮤니티 접점
> **이전 계획 폐기:** 초안은 "`shellrc-doctor`에 JSON 출력 옵션을 요청하는 이슈"를 계획했으나, 실물 확인 결과 `--json`이 이미 구현되어 있어 무효가 되었다. 확인 없이 올렸다면 상대의 README도 안 읽은 셈이 되어 역효과였을 것이다.

**확정: 실제로 써보고 발견한 진짜 문제로 이슈 1건 남기기.** (PR은 범위 밖)

- 대상: `github.com/nord342/shellrc-doctor`
- 전제 조건: 먼저 실제로 돌려본다. 포팅하면서 원본을 여러 fixture로 실행하게 되므로 그 과정에서 발견한 것을 쓴다 — **없는 문제를 지어내지 않는다.**
- 이슈 후보(실제 발견된 것만 채택): `--json` 출력의 스키마 버전 필드 부재 / 특정 셸 문법(다중 라인 `export`, 조건부 `source`, `eval` 안의 PATH 조작) 오탐·미탐 / macOS 특유 경로(`/opt/homebrew` vs `/usr/local`) 처리 사례
- 이슈에 반드시 포함: 재현 가능한 최소 입력(fixture 내용), 기대 동작과 실제 동작, 우리 프로젝트 링크, MIT 하에 로직을 TypeScript로 포팅했다는 사실과 감사 표시
- 시점: D3(8/21). ★0에 3개월 정체된 저장소이므로 답변은 기대하지 않는다 — 이슈를 남긴 사실 자체가 증거.
- 산출물: 이슈 URL과 스크린샷을 결과보고서에 첨부

> 이 추정치는 **인터뷰 이전 값**이며 재계산하지 않았다. 이후 확정된 사항(1인 팀, Build(A) 전환, 어댑터 축소, 제출물 요건 반영)이 반영되지 않았으므로 **목표 설정의 참고로만 쓰고 보고서에는 절대 기재하지 않는다.**

## 증거 자료로서의 CI
GitHub Actions에서 `pnpm test`는 실제 OS 상태에 의존하지 않으므로 그대로 통과한다. **초록 배지가 README에 붙는 것 자체가 심사 자료다** (2-6 기능테스트의 근거). 또한 각 fixture가 골든셋의 실제 사례에서 유래하므로, **"실제로 보고된 문제를 재현하는 테스트"라는 사실 자체가 루브릭 2-6(기능테스트)의 근거**가 된다 — 이는 초록 배지와는 별개의 독립적인 증거다.

Docker 컨테이너 기반 통합 테스트는 v1 범위 밖이다 — macOS 고유 이슈(Homebrew 등)는 컨테이너로 재현되지 않아 비용 대비 효용이 낮다. **시간이 남으면 리눅스에서도 도는 어댑터에 한해 추가한다** (완전 제외가 아니라 조건부 확장 가능성으로 열어둔다).
