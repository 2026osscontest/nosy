# Nosy 메인 캐릭터

`docs/specs/pet-window-spec.md`의 `PetState`(`idle`/`thinking`/`worried`/`alarmed`) 4종에 대응하는 자체 제작 도트(픽셀 아트) 캐릭터와 애니메이션 프레임이다. itch.io 등 외부 CC0/MIT 스프라이트를 채택하지 않고, 코드로 절차적 생성했다 — 출처 고지 의무가 없고(`docs/SUBMISSION.md` 라이선스 체크리스트 대상 아님) `THIRD-PARTY-NOTICES.md`에 기록할 필요도 없다. 배경은 `docs/ADR.md` ADR-001 갱신분 참조.

## 구조
```
assets/character/
  frames.json          상태별 프레임 픽셀 그리드(색상 문자열, 프레임워크 무관) — 통합 시 1차 참고 데이터
  sprites/              원본 해상도(22×18px) PNG. 실제로 <PetView>에 쓸 애셋
    {state}_{n}.png      상태별 개별 프레임 (n = 0..3)
    {state}_sheet.png     상태별 프레임을 가로로 이어붙인 스프라이트시트
  preview/              16배 확대 PNG. 사람이 눈으로 확인하기 위한 용도(실제 렌더링에는 사용하지 않음)
  generator/             생성 스크립트(재현·수정 가능한 원본 소스)
    generate.mjs
    png.mjs               의존성 없는 최소 PNG 인코더
```

## 왜 코드로 생성했나
- 라이선스 걱정이 없는 오리지널 애셋 — 외부 스프라이트 고지 의무 자체가 발생하지 않는다.
- 파라미터(눈 위치·표정·소품)만 바꾸면 상태별 변형·새 프레임 추가가 쉽다.
- `generator/generate.mjs`를 수정한 뒤 아래 명령으로 재생성한다:
  ```
  node assets/character/generator/generate.mjs assets/character
  ```

## 캐릭터 컨셉
이름 그대로 "Nosy"(참견쟁이·코가 예민함)를 시각화했다 — 몸통보다 큰 코가 시그니처 특징이며, 이 코로 개발 환경 구석구석의 문제를 "냄새 맡아" 찾아낸다는 컨셉이다. 다리 없는 둥근 몸통(도토리/젤리형)으로 이동감보다 "화면 한켠에 상주하며 지켜본다"는 인상을 준다. 정수리엔 머리카락 한 올이 나 있다 — 평소엔 느슨하게 흔들리다가(`탄력`), 드래그로 붙잡히면 그 한 올이 팽팽하게 곧추선다(`빳빳해짐`). `alarmed`에선 이 자리를 느낌표(`!`)가 대신 차지하므로 머리카락을 그리지 않는다.

## 헬스 상태 애니메이션 (각 4프레임, 4fps 루프 기준)
| 상태 | 연출 |
|---|---|
| `idle` | 몸통이 1px 위아래로 숨쉬듯 움직이고, 마지막 프레임에 눈을 깜빡인다. 정수리 머리카락도 느슨하게 좌우로 흔들린다 |
| `thinking` | 눈이 오른쪽 위를 보고, 머리 위 점 3개(`···`)가 순서대로 튀어오르며 사고 중임을 표현한다 (점은 머리카락과 다른 위치라 겹치지 않는다) |
| `worried` | 팔자 눈썹 + 물결 입 + 관자놀이 옆 땀방울이 4프레임에 걸쳐 흘러내린다. 머리카락도 평소보다 더 축 처져 흔들린다 |
| `alarmed` | 몸통이 좌우로 흔들리고(shake), 머리 위 빨간 느낌표(`!`)가 함께 흔들린다 (이 상태만 머리카락 대신 느낌표가 그 자리를 차지) |

## 모션 레이어 (`PetState`와 별개 축)
`docs/specs/pet-window-spec.md`의 `PetState`(idle/thinking/worried/alarmed)는 **헬스 스코어가 결정하는 표정**이고, 아래는 **마우스 상호작용/이동이 결정하는 몸짓**이다 — 서로 직교하는 별개 축이므로 동시에 조합될 수 있다(예: `worried` 표정으로 걸어다니기). `<PetView>` 연동 시 이를 `PetState`에 억지로 끼워 넣지 말고 별도 prop(예: `motion?: 'walking' | 'dragged'`)으로 넘기는 것을 권장한다.

| 모션 | 트리거 | 연출 |
|---|---|---|
| `walking` | 무입력 idle 중 자체 이동(`docs/UI_GUIDE.md`의 "천천히 돌아다님") | 제자리 통통 튀는 홉(hop) — bob으로 몸통을 -3px까지 띄우고, 바닥에 반투명 그림자를 깔아 착지/도약을 표현한다. 좌우 실제 이동은 이 프레임이 아니라 `<PetView>`를 감싼 창 위치 애니메이션이 담당한다 |
| `dragged` | 마우스 다운으로 펫을 집어 든 순간 ~ 드래그 종료 전까지 | 정수리의 머리카락 한 올(`HAIR_X`/`HAIR_BASE_ROW`)이 잡힌 지점(pivot)이다 — 평소의 느슨한 드룹(`paintHairLoose`) 대신 잡아당긴 방향으로 팽팽하게 뻗는다(`paintHairTaut`). 몸통은 이 정수리 pivot 아래로 매달린 형태라 `tiltShear`가 온몸을 **한 방향으로만** 기울인다(정수리에 가까울수록 덜 흔들리고 발치로 갈수록 많이 흔들림) — 이전의 볼-꼬집기 방식처럼 머리와 몸이 서로 반대로 꺾이지 않는다. 프레임 0-1은 몸통이 왼쪽으로 쏠리며 머리카락은 오른쪽으로 뻗고(= 오른쪽으로 드래그될 때의 관성), 프레임 2-3은 그 반대(왼쪽으로 드래그) — 좌우가 완전히 대칭이라 어느 방향으로 끌어도 자연스럽다. 눈은 놀란 표정(`surprised`)에 입은 벌어진 채(`mouth: "o"`) |

`walking`은 4프레임/4fps로 다른 상태와 동일한 리듬을 유지한다.

## 연동 지점
`packages/core`의 `Finding`/헬스 스코어에서 파생되는 `PetState`를 받아 `apps/pet`의 `<PetView state={...} />`(`docs/specs/pet-window-spec.md` FR-003, ADR-001)에서 `sprites/{state}_{frame}.png`를 프레임 전환하며 그린다. 픽셀이 흐려지지 않도록 렌더링 시 `image-rendering: pixelated`(CSS) 또는 캔버스의 `imageSmoothingEnabled = false`를 반드시 적용한다.
