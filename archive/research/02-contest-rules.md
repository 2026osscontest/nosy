### 3.1 참가 자격

| 항목 | 내용 |

| 학생부문 | 초·중·고교생 및 대학(원)생 (재학·휴학생 포함) |
| 일반부문 | 학생부문에 해당하지 않는 자 |
| **혼성팀** | 학생+일반 혼합 시 **반드시 일반부문으로 참가** (규정 제4조 ②, 제6조 ④) |

| 증빙 | 운영사무국이 대회 중·수상 후 언제든 증빙 제출 요구 가능 (제4조 ④) |

> 참고: overview 페이지에는 학생부문을 "고교생 및 대학(원)생"으로, 운영규정 PDF와 oss.kr에는 "초·중·고교생 및 대학(원)생"으로 표기. **운영규정이 우선**이므로 초·중생도 학생부문.

> `[확인]` **개발 시작 시점 제한 조항은 운영규정 어디에도 없습니다.** 즉 **대회 이전부터 개발해 온 기존 프로젝트의 출품 자체는 금지되지 않으며**, 제약은 오직 "정부 지원사업 중복 수혜"뿐입니다. 또한 **민간 대회 중복 출품 금지 조항도 없습니다.**

### 6.6 AI 모델 활용 기준 (제9조 + [별표2] + [부록2]) — 실격 위험 높음

**세 개의 관문 (전부 충족해야 사용 가능)**

1. **가중치 공개**: 최소 **오픈웨이트 이상**. 승인된 특정 인원만 받을 수 있는 폐쇄형 모델 불가. (권장: OLMo·Pythia 등 오픈소스 AI / 최소기준: LLaMA·Mistral·Qwen·Gemma·SOLAR)
2. **독립 구동 가능성**: 로컬·자체 서버·직접 관리하는 클라우드 GPU에서 실행 가능해야 함. **"외부 상용 API 호출로만 작동하는 모델을 서비스 형태로 단순 연결"한 출품작은 제한.**
3. **산출물 라이선스**: 직접 작성한 학습·추론 코드에 **OSI 인증 라이선스 필수**. 기반 모델이 파생물 라이선스를 강제하면 그쪽이 우선.

**판정 사례표 (부록2 원문)**

| 상황 | 판정 |
|---|---|
| Llama/Gemma/Qwen/Mistral을 내 서버에서 실행 | 가능 |
| 빌린 클라우드 GPU에 오픈웨이트 모델 올려 구동 | 가능 |
| 음성인식·이미지인식·**임베딩** 등 소형 공개 모델 사용 | 가능 |
| **외부 상용 API를 빼면 핵심 기능이 전혀 작동 안 하는 서비스** | **제한** |
| 외부 상용 API를 쓰되 오픈웨이트 모델로도 같은 기능 작동하도록 함께 구현 | 가능 |
| **LangChain 등 오픈소스 라이브러리를 거쳐 외부 상용 API 호출** | **제한** (래퍼를 둘러도 동일 판단) |
| **MCP 서버/커넥터/에이전트 프레임워크 개발** + 연동 테스트용 API 호출 | **가능 · 권장** |
| 출품작엔 모델 없이 시연·성능측정에만 외부에서 로컬 모델 구동 | 붙임2 면제 |
| 파인튜닝한 새 가중치를 비공개 유지 | **불가** |
| 파인튜닝 결과를 LoRA 어댑터 형태로만 공개 | 가능 |
| 비상업·학술 전용 조건 모델 사용 | 사실상 불가 |
| 라이선스가 파생물 공개를 금지하는 모델 | 사전 확인(다른 모델 권장) |
| ChatGPT/Claude 도움으로 코드 작성 | 가능 |
| **AI가 짜 준 코드의 동작 원리를 설명 못함** | **감점 요인** |

> `[확인]` 공지 36번: **OpenAI Embedding API 등 상용 API 임베딩 모델도 제한 대상.** BGE·E5·KoSimCSE 등 오픈웨이트 임베딩 모델을 직접 내려받아 구동하면 가능.
> `[확인]` 부록2 Q6: **대회는 서버·GPU·AI API 크레딧 등 인프라를 일절 지원하지 않음.** 보유 자원에서 실제 구동 가능한 규모의 모델을 선택할 것.
> 판단이 애매하면 **개발 착수 전** contest@oss.kr로 모델명·라이선스 링크 첨부해 문의(제출 후 확인되면 되돌리기 어려움).

### 11.2 라이선스 검증 5점 만점용 (저장소 정합성)

- [ ] **저장소가 Public** 상태 (수상 시 5년간 유지 의무)
- [ ] 저장소 최상위에 **`LICENSE` 파일** — OSI 인증 라이선스 전문 그대로. **MIT 또는 Apache-2.0 단일 라이선스 권장**(충돌 위험 최소)
- [ ] `README.md`에 **라이선스 배지/섹션** 명시 (SPDX 식별자로: `MIT`, `Apache-2.0`)
- [ ] **단일 라이선스 정합성**: `LICENSE` 파일 / `package.json`의 `"license"` 필드(또는 `pyproject.toml`, `pom.xml`, `build.gradle`) / README 표기 **3곳이 완전히 동일**해야 함. 불일치는 자동 검증 도구가 즉시 잡아냄
- [ ] **GPL 전염성 회피 점검**: 의존성 중 **GPL / AGPL / LGPL 계열**이 있는지 확인. 있다면 —
  - [ ] 링크 방식 확인(정적/동적/별도 프로세스) 및 결합 방식을 SBOM '사용 목적'에 기재
  - [ ] 본체를 MIT/Apache-2.0으로 배포하면서 GPL 라이브러리를 정적 링크하면 **충돌**. 대체 라이브러리로 교체하거나 본체 라이선스를 맞추는 결정을 **지금** 할 것
  - [ ] **Apache-2.0 코드를 GPL-2.0-only 프로젝트에 넣는 조합은 비호환** — 이 조합을 피할 것
- [ ] **`NOTICE` 파일** — Apache-2.0 의존성을 쓰거나 본체가 Apache-2.0이면 필수 관행. 저작권 고지·귀속 표시 수록
- [ ] **`THIRD_PARTY.md`** — 붙임1 SBOM과 동일 내용을 저장소 최상위에 배치 (`[확인]` 공식 가이드가 명시적으로 권장)
- [ ] 각 소스파일 상단에 **SPDX 헤더** 삽입 권장: `// SPDX-License-Identifier: MIT` + 저작권 표기
- [ ] **복사·붙여넣기한 남의 코드**를 전수 색출해 SBOM과 해당 파일 주석에 출처·라이선스 명시 (`[확인]` "2차 평가의 소스코드 분석에는 그대로 확인됨")
- [ ] 폰트·아이콘·이미지·데이터셋 등 **비(非)코드 저작물의 라이선스**도 확인 (예: Pretendard GOV — 대회 사이트도 별도 라이선스 고지 공지를 게시함)

- [ ] SBOM 표의 **버전은 실제 설치 버전**(범위 표기 금지), **라이선스는 SPDX 공식 표기**

### 11.3 기능테스트 10점 만점용 (재현성·안정성)

- [ ] **빌드 재현성**: 클린 환경(새 클론)에서 문서만 보고 빌드·실행이 성공하는지 **제3자 검증** 완료
- [ ] **원커맨드 실행 경로** 제공: `docker compose up` 또는 `make run` 또는 단일 스크립트
- [ ] **설치 문서**(README): 필수 런타임/버전 명시, OS별 주의사항, 의존성 설치, 환경변수 목록, 실행 명령, **예상 출력/스크린샷**

- [ ] **외부 유료 API 없이 동작하는 경로**가 존재 (AI 모델 사용 시 **규정상 필수**). 없으면 실격 위험

- [ ] **테스트 코드 + CI**: GitHub Actions로 빌드·테스트 그린 배지. 커버리지 수치 자체보다 **"CI가 돌고 있다"는 사실**이 1차 '관리체계' 6점에도 직결
- [ ] **시드 데이터/샘플 입력** 동봉 — 심사자가 즉시 돌려볼 수 있게
- [ ] 결과보고서 '구동 및 시연' 항목에 **실행·테스트 방법을 구체적으로** 기재(심사기준 명시 항목)
- [ ] 시스템 구성도 / 아키텍처 다이어그램 — 기능테스트 제출자료 "시스템 소개서" 역할
- [ ] 리소스 요구사항 명시(GPU 필요 여부, 최소 RAM 등). **대회는 인프라를 지원하지 않으므로** 심사자 환경에서 돌아가는 규모여야 함
